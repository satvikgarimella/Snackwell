# FP32 execution in Snackwell

The four-warp, four-lane SM executes `FMUL`, `FADD`, and `FSUB`. Each instruction
reads two registers per active lane and writes one destination register per
active lane. Registers hold raw binary32 bits; integer operations do not convert
them to or from floating point.

## Instruction encoding

The existing 32-bit format is unchanged:

| Bits | Field |
| --- | --- |
| 31:26 | Opcode |
| 25:22 | Destination register |
| 21:18 | Source 1 register |
| 17:14 | Source 2 register |
| 13:0 | Unused for FP operations; encode as zero |

| Instruction | Opcode | Lane operation |
| --- | --- | --- |
| FMUL | `0x0C` | `Rd = Rs1 * Rs2` |
| FADD | `0x0D` | `Rd = Rs1 + Rs2` |
| FSUB | `0x0E` | `Rd = Rs1 - Rs2` |

For example, the testbench encoding for `FMUL R3, R1, R2` is
`{OP_FMUL, 4'd3, 4'd1, 4'd2, 14'd0}`.

## Execution and completion

`simd_fp32_execute` shares four existing scalar multiplier wrappers and four new
iterative add/subtract units across all warps. It accepts one SIMD FP instruction
at a time. The add/subtract units align exponents, add or subtract significands,
normalize, and round over multiple cycles. This is a functional implementation,
not a throughput-optimized FP pipeline.

The SM captures the warp ID, destination, and active mask when an FP instruction
issues. Each active lane can finish at a different time; the SIMD unit completes
only after all have finished. An empty mask completes without starting any lane.
Requests presented while the unit is busy are ignored.

Source dependencies (RAW) and destination dependencies (WAW) prevent premature
issue. Busy state is per warp and register, conservatively covering every lane.
Operands are captured at acceptance, so younger writes to source registers do
not change an operation already in flight. Independent integer, memory, and
control instructions may continue while FP runs.

The shared writeback slot gives priority to an FP completion, then a tensor row,
then a completed shared-memory load, then a newly issued integer result.
Integer writers retry when a completion reserves that slot. An older writeback
may retire on the same edge that the slot accepts the FP result. A destination
stays busy until the register file actually commits its write. Shared-memory
requests serialize conflicting lanes; see [the memory documentation](MEMORY.md).
Resource-stalled warps retry without requiring a writeback from their own warp.

`run_enable=0` pauses issue while accepted work continues to completion. Debug
register writes backpressure architectural writeback; results and completion
tags remain held until that port is available. `EXIT` waits for the selected
warp's pending register writes and memory request, including stores.
Reset aborts in-flight operations and clears the
scoreboard. Launch an unused or fully retired warp; launching over live work is
not a context-switch mechanism.

Reconvergence changes PC/mask/stack state only when its internal control operation
is accepted. FP results retain their original mask even if control flow changes
the warp's active mask before writeback.

## Numeric behavior and limits

- Binary32 arithmetic with round-to-nearest, ties-to-even.
- Signed zeros, infinities, NaNs, overflow, and gradual underflow/subnormals.
- Add/subtract returns a canonical quiet NaN. The existing multiplier's NaN
  representation may differ; tests compare NaN classification rather than payload.
- No FP exception flags, selectable rounding modes, conversions, or fused MAC.
- One outstanding SIMD FP operation globally; latency depends on operands.
- This milestone is validated in simulation. FPGA synthesis and timing remain
  later roadmap items. The 4x4 systolic array also executes through the SM's
  `TMUL` instruction; see [the tensor documentation](TENSOR.md).

## Tests

Install Python 3 and Icarus Verilog (`iverilog` and `vvp`), then from the repository:

```sh
python3 scripts/run_tests.py
```

To run only the new suites:

```sh
python3 scripts/run_tests.py tb_simd_fp32_execute tb_snackwell_sm_fp32
```

The runner compiles every testbench separately, uses bounded simulation timeouts,
rejects implicit nets and floating input ports, and saves logs and waveforms under
`build/tests/`. It generates deterministic vectors using an independent Python
oracle with exact integer arithmetic and one final nearest-even rounding step.

`tb_simd_fp32_execute` checks 3,975 four-lane vector groups, including more than
15,000 active lane results across all three operations, every active mask,
cancellation, rounding ties, subnormals, special values, random bit patterns,
busy request rejection, input changes after acceptance, and reset.

`tb_snackwell_sm_fp32` covers four competing warps, dependent FP chains, integer
and shared-memory consumers, masked and empty warps, WAW ordering, independent
integer progress, FP/integer/load writeback collisions, divergence/reconvergence,
writeback backpressure, pause/resume, EXIT draining, and reset/relaunch.

The older suites also run. Stale testbench connections for the LSU, register file,
warp scheduler/control, and reconvergence target table have been updated to match
their current interfaces. Issue-stage and issue-control tests now also check WAW
hazards and recovery from resource stalls.
